# Askaha

一个 Windows 桌面端数据库智能体: 你用自然语言提出任务, 智能体自动规划 SQL、查询数据库、生成 HTML/Markdown 报告。

## 功能

- 多数据库支持: MySQL / PostgreSQL / SQLite / SQL Server
- 兼容 OpenAI 协议的大模型接口 (OpenAI / DeepSeek / 通义千问 / 智谱 / 自建网关等)
- 按需确认: 开工前先判断条件是否充分, 充分就直接查, 不充分只问缺的那一项
- 智能体 ReAct 风格循环: 规划 → 执行 SQL → 观察结果 → 继续, 最多 12 步
- 报告生成: HTML 报告带样式预览, 同时产出 Markdown
- Skills 导入: 单个 `.md` 文档或含脚本/多份文档的文件夹
- 多数据库管理: 每个库各自勾选可访问的表, 没有"当前库"这一说
- 流程卡导入导出: 卡打包成 JSON 在同事之间传, 卡包里带上"连的是哪个库"的说明但**不带口令**, 导入时自动认到本机对应的库

## 工作流程

一次任务大致是这样走的:

```
用户发言
  └─ 意图闸门 (先判断"在跟你说话"还是"让你干活", 这一步不碰数据库)
       ├─ 在跟你说话 ──→ 直接回答, 到此结束 (不出报告, 不碰库)
       └─ 让你干活 ────→ 读取可访问表(仅表名) → 工具循环
                            └─ 按需: 选表 / 选字段 / 写 SQL / 出报告
```

- **意图闸门**: 动手之前先分清这是闲聊还是取数。闲聊只回一句话, 不读表、不弹窗、不出报告 —— 所以等待期间界面上不会冒出"正在读取可访问的表"这类取数步骤。这个判断需要单独一次模型调用
- **判不出来就当取数**: 闸门返回异常、格式不对、调用失败, 一律按"干活"处理。多走一遍流程只是慢一点; 把真需求当闲聊回掉是功能故障
- **可选范围由你勾选**: AI 只能访问在「数据库」页勾选的表, 范围外的表不查询、不猜测
- **跨库自动定位**: 勾过的表不分库合成一份白名单, 每条 SQL 按里面出现的表名反推该连哪个库 —— 所以不需要先选"用哪个库"。一条 SQL 同时用到两个库的表会被拦下并提示拆开取数; 两个库有同名表时不猜, 让你去只勾其中的一张
- **表结构按需取**: 选表阶段只有表名与你的备注, 不读取表结构; 表确认之后, 才对本次要用的表读一次字段
- **会话是有状态的**: 已确认的表/字段、跑过的 SQL 及其结果都会带进下一轮。"把图重画一下""换个配色"这类要求直接出报告, 一条 SQL 都不会重跑
- **唯一硬闸门是 SQL 执行确认**: 每条 SQL 执行前逐条预览。这是只读模式下最后一道人眼把关
- **自动决策可见**: 智能体替你定下的表与字段会以 `AUTO` 步骤写在对话里, 不会悄悄发生

## 空环境也能用

刚装好还没配置数据库时, 界面不会拦着你说话 —— 闲聊照常回复。只有真正发起取数任务时才会提示去配置:

- **不拦的**: 打招呼、问能力、问软件怎么用、闲聊
- **要拦的**: 没有 API Key (任何调用都跑不起来, 发送前直接挡住)
- **取数时才引导**: 没配库 / 没勾表 → 任务明确失败并自动跳到「数据库」页

## 数据表清单与备注

在「数据库」页, 每个数据库下方都有一块可展开的表清单。

- **探测数据表**: 读取当前库的表名。只取表名, 不读取任何表结构
- **查看数据表**: 展开 / 收起表清单
- 表清单里每张表显示为一张卡片: 表名、下方是可写的备注、右侧是复选框, 一行至少 5 张
- 折叠栏右上角可按 **全部 / 已勾选 / 未勾选** 筛选, 也可以按表名搜索
- **勾选**决定 AI 能访问哪些表; **一张都没勾选**时任务会被拦下并提示先去勾选
- **备注**是选填的, 用来交代这张表是干什么的、口径如何。AI 在选表阶段看不到字段, 只依据表名与备注判断, 备注写清楚能明显提升选表准确度

重新探测会保留已有的勾选与备注 (按表名对应), 不必担心白填。

## 快速开始

```bash
# 1) 安装依赖
npm install

# 2) 启动应用
npm start

# 3) (可选) 跑安全回归测试
npm test
```

如果启动时窗口没有出现, 控制台刷出一串 `GPU process exited unexpectedly`, 最后是
`FATAL: GPU process isn't usable. Goodbye.`, 说明当前环境的硬件加速不可用
(常见于远程桌面 / 虚拟机 / 显卡驱动异常)。改用兼容启动方式即可:

```bash
npm run start:compat   # 带 --no-sandbox, 关闭进程隔离换取可启动
```

兼容脚本会降低进程隔离级别, 只在默认方式起不来时使用, 不要长期替代 `npm start`。

首次启动后:

1. 切到 **设置 · 模型**, 填写 `Base URL` / `API Key` / `Model`, 保存
2. 切到 **数据库** 标签, 点击 **添加数据库**, 填写连接信息, 可先 **测试连接** 确认
3. 在数据库下方点击 **探测数据表** 读取表名, 勾选本次要访问的表 (建议顺手写一句备注)
4. 切回 **对话** 标签, 在底部输入任务并发送 (Ctrl+Enter 发送)

## 设置

设置页是左右两栏: 左边是设置项目录 (2 成宽), 右边是操作面板 (8 成宽)。

### 模型

`Base URL` / `API Key` / `Model` / `Temperature` / `Max Tokens`。改完立即生效, 不用重启。

`API Key` **不回显**: 主进程只下发"配没配"这一个布尔, 明文密钥不出主进程, 也不写进渲染层。
输入框留空表示不修改已保存的那把 (所以改模型不会把 Key 抹掉); 要清空请点提示里的
**清除已保存的 Key**。数据库口令同理, 同样不下发到界面。

`Max Tokens` 注意给宽一些: 推理模型的思考过程也算进这份配额, 给小了正文会被截断。
程序检测到截断会自动翻倍重试一次。

### 提示词

系统提示词按模块拼装, 可以逐块改。点左侧模块名切换编辑对象, 改动只影响被改的那一块,
没动过的跟随出厂版本 —— 这样以后出厂提示词升级了, 你没动过的部分会自动跟上。

| 模块 | 作用 |
| --- | --- |
| 身份 | 智能体是谁、干什么的 |
| 意图分流 | 先分清"在跟你说话"还是"让你干活" |
| 取数判断 | 手上的资料够不够办这件事 |
| 动作协议 | 动作只能通过工具调用表达 (锁) |
| 输出格式 | html / excel / none 由模型自己判断 |
| SQL 门面 | purpose / rationale / fields 怎么写 |
| 报告要求 | insights / charts / kpis 怎么写 |
| 硬约束 | 可访问范围、SQL 只读、禁止探测系统表 (锁) |

标 **锁** 的两个模块承载的是协议与安全边界, 只能改文字、不能关闭 ——
关掉「动作协议」模型会往正文里写 XML 方言, 关掉「硬约束」可能越界访问白名单外的表。

顶部三个按钮: **预览全文** (看改完保存后会是什么样, 不必先保存)、**恢复出厂**、**保存**。

有三块内容是运行期注入的, 不参与配置, 因为它们改了就破协议:

1. **技能清单** — 只放技能名和用途, 智能体需要时才会加载完整内容
2. **工具定义** — 内置动作 + MCP 外部工具的 schema (走原生 function calling 通道, 本身也是提示词)
3. **每轮的用户消息** — 当前会话状态 (已确认的表与字段、已有资料编号) + 本次要求

### 通用

| 项 | 默认 | 说明 |
| --- | --- | --- |
| 单轮最大步数 | 16 | 一次任务里最多允许模型做多少步。调小防跑偏, 调大给复杂分析留余地 |
| 回灌历史轮数 | 6 | 每次任务带给模型的最近几条对话。填 0 表示不带历史 |

### 流程引擎 · 流程卡包

流程卡是写死的确定性流程, 天生适合在同事之间传 —— 但卡里记的是"连哪个库", 而库的 id
每台机器都不一样。直接拷过去, 对方拿到的是一张跑不出结果、界面上还不报错的卡。
所以导入导出走"卡包"这条路。

**导出**: 流程引擎页右上「导出」, 或单张卡右上角的 `⤓` (只勾那一张)。可以一次选多张。
产物是一个 JSON 文件 (`*.solodb-cards.json`), 除了卡本身, 只记下每张卡用到的库的
**类型 / 地址 / 端口 / 库名** —— 用来让对方认库, **不含口令和用户名**。

**导入**: 流程引擎页右上「导入」, 支持一次选多个卡包文件。落盘之前先摆三件事:

| 看什么 | 为什么 |
| --- | --- |
| 库对应关系 | 卡包里的库认到了本机哪个库。按 地址完全一致 → 仅名字相同 → 手工指定 的顺序认, 认不出的可以下拉手工指 |
| 同名卡怎么办 | 跳过同名 / 覆盖同名 / 都存成新卡 (名字后加「(导入)」) |
| 哪些卡不能导 | 依赖的库没认出来的卡会被拦下, 指认之后才能勾选 |

导入是"注册进配置", 之后在对话里就能命中; 写盘失败会整体回滚, 不会留下半套卡。

## 技能 (Skills) 格式

技能可以是以下两种形态之一。

### 形态 A: 单个 Markdown 文件

带 YAML frontmatter, 正文即为注入到 Agent 的系统提示。

```markdown
---
name: orders-domain
version: 0.1.0
description: 电商订单域背景知识
---

本技能注入订单域的业务知识...

- 表 `orders.status` 取值: created / paid / shipped / ...
- 字段 `amount` 单位为分
```

### 形态 B: 文件夹

`my-skill/`
- `SKILL.md` — 主清单 (frontmatter + 正文) , 与 `skill.json` 二选一
- `skill.json` — 兼容旧版 (字段: name / version / description / systemPrompt / examples)
- `extra.md` 等附加 `.md` 文件 — 自动拼入系统提示
- `*.js` 脚本 — 启动时自动 `require`, 作为运行时辅助

#### frontmatter 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | 是 | 技能名, 缺省回退到目录名/文件名 |
| `version` | 否 | 默认 `0.1.0` |
| `description` | 否 | 一句话说明 |
| `entry` | 否 | 指定入口 JS 文件, 不填则自动加载目录内所有 `.js` |
| `examples` | 否 | 一行一个示例 (用 `  - ` 列表) |

## 导入方式

在 **技能** 标签页:

- 点击 **导入 .md** 选择一个 Markdown 文件
- 点击 **导入文件夹** 选择一个包含 `SKILL.md` 或 `skill.json` 的目录
- 导入后用开关启用/停用

## 安全

- 智能体在 MVP 阶段仅允许执行**单条** `SELECT` / `WITH` / `EXPLAIN` / `PRAGMA` 语句
- 校验前会先剥离注释与字符串字面量, 并在骨架文本上做三重检查: 语句开头必须是只读动词、分号后不得再有内容、不得出现写操作关键字 (可拦住 `WITH ... DELETE` 这类伪装)
- 骨架按**方言**决定怎么读字面量: 反斜杠只有 MySQL 默认模式下才是转义符。PostgreSQL / SQL Server / SQLite 里它是普通字符, 按 MySQL 读会把真实代码整段吞掉 (`SELECT 'a\' ; DROP TABLE t ; -- '`), 所以那几个库按"不转义"读 —— 宁可多报一次错, 也不能漏掉一条真会执行的语句
- 静态校验之外, MySQL / PostgreSQL 的会话会被设成**只读事务**, 由数据库在执行层再拦一道写操作 (设置失败只记警告, 不影响建连)
- 校验失败会直接报出原因, 不会把语句透传给数据库
- 无论条件多充分, SQL 执行前都会把语句交给你确认, 这道闸门不会自动跳过
- 智能体的可访问范围由你勾选的表决定; 模型请求范围外的表会被拒绝, 且不会触达数据库
- 提示词中明确禁止通过 `information_schema` / `sqlite_master` / `SHOW TABLES` 等方式去发现其它表
- 报告在 `sandbox="allow-scripts"` 的 iframe 里渲染, 拿不到应用页面的 `window.bridge`; 图表数据里所有 `<` 都会转义成 `\u003c`, 数据库单元格的值无法闭合脚本块
- API Key 与数据库密码仅保存在本地用户目录 `config.json` 中, 不外发; 且**不会下发到渲染层** (界面只拿到"配没配"的布尔)
- 窗口被钉在应用自己的页面上: 外链交给系统浏览器, 不在应用窗口里打开
- 所有数据库连接只在本地发起, 不经任何第三方服务

> 待办: 尚未设置 CSP。报告是在 `srcdoc` iframe 里跑内联脚本的, 而 `srcdoc` 会继承父页面的 CSP, 所以策略需要连同报告渲染一起验证后再加, 不能只贴一行 `script-src 'self'` 了事。

## 数据库连接

每个任务开一条连接, 读表结构、看字段、执行查询都复用它, 任务结束统一回收。

同一个任务内反复建连的代价不小: SQLite 会反复读盘并重新解析整个库文件, MySQL / SQL Server 则会每次新建连接、旧连接失去引用无法回收。连接在第一次用到时就建立, 后续调用共用, 结束后复位。
