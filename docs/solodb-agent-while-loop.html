SoloDB · Agent 核心 while 循环

源码位置 lib/agent-loop.js 的 AgentLoop.run()（359–530 行）。 三个 Agent（分析 / 搭建 / 测试）共用这一份实现，循环体只有 6 步。
循环主干 回边（这就是"while"） 出口 / 提前返回 不消耗预算的纠正路径

循环的形状：无上限 + 7 个 return

  • 写法是 for (;;) —— 没有步数上限写在循环条件里
  • 退出全靠 return this._result()，一共 7 处
  • 真正防死循环的是开头的 ①② 两道判定
  • 这是有意的：让"什么时候停"由策略决定，不由计数器隐式决定

纠正路径不消耗预算

  • 模型编工具名 → continue 回开头，不 steps++
  • 理由：它没真的做成任何事，不该扣预算
  • 但不扣就得限次数 —— MAX_CONSECUTIVE_RETRIES = 3
  • 不设限的话一个持续编工具名的模型会让循环永远转、内存一路涨

每轮都在重算的三样东西

  • 上下文压缩：超阈值就把旧结果折成存根
  • 进度账：从现存存根反推，无条件更新（不是"折了才更新"）
  • 系统提示：systemWithLedger() 每轮现拼
  • 用户原话全程逐字不动 —— 账进系统提示而不是消息数组

工具执行的并发规则

  • 一轮里有多个调用 且全部只读 → Promise.all 并发
  • 只要有一个有副作用 → 整轮串行
  • 实际很少触发：多数轮只有 1 个调用
  • 工具抛错也入账（finally 里记）—— "又慢又挂"的最该被看到
